# TDK SaaS Starter Demo Guide

## Run the Project

From the project root:

```bash
cd tdk-saas-starter
```

Make sure Docker/Colima is running before using Tilt-managed containers:

```bash
colima start
docker info
```

Regenerate the TDK project output after changing `.tdk/project.json`, `service.json`, or TDK CLI generation code:

```bash
tdk project --yes
```

Start the full SaaS landscape:

```bash
tdk up
```

Or start one domain stack:

```bash
tdk up app
tdk up billing
```

TDK discovers four resources from `service.json` manifests across the `app` and `billing` stacks.

## Local Browser URLs

When the local HTTP bridge or Traefik proxy is running, use these URLs:

```text
Dashboard app: http://dashboard-app.app.tdk-saas-starter.localhost/
Checkout app:  http://checkout-app.app.tdk-saas-starter.localhost/

App API:     http://api.tdk-saas-starter.localhost/api/dashboard-management
Billing API: http://api.tdk-saas-starter.localhost/api/billing-management
```

Direct service ports are:

```text
dashboard-api   http://localhost:4200/health
dashboard-app   http://localhost:3200
billing-api     http://localhost:4210/health
checkout-app    http://localhost:3210
```

## Direct Dev Server Fallback

If Docker/Tilt is not available, run the services directly with Bun/Vite:

```bash
(cd services/app/dashboard-api && bun run dev)
(cd services/app/dashboard-app && bun run dev)
(cd services/billing/billing-api && bun run dev)
(cd services/billing/checkout-app && bun run dev)
```

Each command runs a foreground process. Use separate terminals, or run only the resources needed for the demo.

## Three-Minute Walkthrough

### 1. Start the landscape

```bash
tdk up
```

Show that TDK discovers the four SaaS resources and generates `.autogenerated/` files for each resource.

### 2. Inspect the billing service boundary

Open `services/billing/billing-api/service.json` and point out the PSR contract: `appName`, `appType`, `stack`, `port`, `dependsOn`, and health check.

### 3. Walk through the product

- App: live MRR, growth, churn, and account activity on the dashboard.
- Billing: pricing plans and a Subscribe button that calls `/api/v1/checkout-session`.

### 4. Click Subscribe

Open `checkout-app` at `:3210`, pick a plan, and click **Subscribe**. The panel below the plans fills in with the mock session id, amount, and checkout URL returned by `billing-api`.

### 5. Start one stack

```bash
tdk up billing
```

Use this to show how the billing domain can run without booting the dashboard.

### 6. Extend the example

```bash
tdk resource invoices-api --type backend --stack billing
tdk stack billing
tdk up billing
```

The new service follows the same manifest-driven workflow as the existing SaaS starter resources.
